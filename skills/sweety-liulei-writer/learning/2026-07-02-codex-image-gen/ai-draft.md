先说个把我烦了挺久的小事。我平时在 Claude Code 里干活，写文案、排版、跑流水线都在这儿，唯独生图这一步卡壳——我的图走的是 Codex 桌面 app 里那个内置生图，于是每次都得：在 Claude Code 里把 prompt 攒好，切窗口到 Codex，贴进去，等它出，再把图捞回项目里。一张两张还行，一套八九张连封面，来回转手转到我烦。就想着，能不能让 Claude Code 自己就把图生了，别每次让我当二传手。

## 我一开始想歪了，得先泼自己一盆冷水

我最初的念头很朴素：装个插件呗，`codex@openai-codex` 什么的，装上 Claude Code 不就有生图了。想当然。真去捋才发现这条路根上就不通，而且不是"没找到那个插件"，是三层都堵死：

其一，**Claude 本身不会生图**。Anthropic 没出图像模型，Claude 是个纯文本的脑子，你给它挂多少插件，它也变不出一张图，生图这活儿永远得靠某家的图像模型去干。其二，**Codex 那个"内置生图"不是一块能搬走的积木**，它是 OpenAI 的 gpt-image，绑在你的 ChatGPT/Codex 订阅登录上的。我 pipeline 里那个 `requiresApiKey: false` 能成立，唯一原因就是我人在 Codex app 里、用的是订阅登录——这个"免 key、订阅内"的通道只在 Codex 自己家里存在。其三，插件搬不动别家的订阅授权，这是常识，别指望。

所以"装个插件让 Claude Code 会生图"是个伪命题。想通这点，问题就变了：我要的不是"让 Claude 学会生图"，是"别让我手动转这一手"。这俩不是一回事。

## 两条路，我为什么选了更麻烦的那条

摆在面前的其实是两条：

一条是给 Claude Code 挂个图像 MCP，OpenAI 的 Images API、或者 Gemini、Flux 都行，我这边直接就有个生图工具，零切换。听着最爽。代价是三条：要 API key、按张真金白银计费（不是我订阅里那条免费的）；换了模型，画风大概率跟我现有的成图对不上；而且我整套流水线里白纸黑字写着"必须 codex-builtin、不许拿 API 脚本替代正式生图"——上这条等于自己破自己的规矩。

另一条更绕：OpenAI 有个官方的 `codex` 命令行版，跟桌面 app 是同一个 Codex agent，用同一个账号登录。要是它的无头模式能生图，那我就能在 Claude Code 里用 Bash 去调它，人还在 Claude Code，底下是 Codex 在干活——还是订阅登录、还是免 key、画风还一致，我那条"不许 API 脚本"的规矩一条没破。

我选了后者。理由很简单：我那套"codex-builtin、免 key"的纪律不是拍脑袋定的，是为了省钱、画风一致、来源可溯。为了省事去破它，不值。**能用，但前提是它无头模式真能调出生图**——这点我当时没底，所以没吹牛，先去测。

## 真去测了，一步步来

装：

```bash
npm i -g @openai/codex
```

出来 `codex-cli 0.142.5`，`codex exec` 这个非交互子命令在。先别急着高兴，`exec` 那个 `-i/--image` 是给你**喂**输入图的，不是**产出**图，两码事。

关键得确认两件：登录方式、和生图工具在不在。翻 `~/.codex/auth.json`：

```
keys: ['auth_mode', 'OPENAI_API_KEY', 'tokens', 'last_refresh']
has OPENAI_API_KEY: False
has chatgpt tokens: True
```

`OPENAI_API_KEY` 是空的，ChatGPT 的 token 在——这正是我要的那条免 key 通道，它跟桌面 app 共用 `~/.codex`，我之前用 app 登录过，CLI 直接就认了（doctor 里躺着 493 个历史会话、21 个 G，可见共用得很彻底）。再查 feature：

```
codex features list | grep image
image_generation    stable    true
```

`stable`、`true`，开着的。到这儿理论上全通了，但理论归理论，得让它真吐一张图出来才算数。前台跑一发，让它画个蜡笔红苹果落地成 png：

```bash
codex exec -C "$PWD" -s workspace-write --skip-git-repo-check \
  "用你内置的 image_generation 工具（别拿 API、脚本、SVG 替代）生成一张：白纸上一个蜡笔画的红苹果，儿童涂色风格。保存为当前目录 codex-imgtest.png。"
```

（这里有几个坑位参数：`-s workspace-write` 不给它就写不出文件；非 git 目录必须 `--skip-git-repo-check`，不然它罢工。）

等了一会儿，`codex-imgtest.png` 真出来了，1254×1254，两百来 K……不对，是 2.1M。打开一看，一个歪歪扭扭的蜡笔红苹果加片绿叶子，正是我要的儿童涂色感。**通了**。人在 Claude Code 没动窝，底下 Codex 把图生了，免 key，一张烧了大概 5 万多 codex token——走订阅额度和限速，不是美元账单。

## 通了之后冒出来两个坑

高兴完得较真。我盯着那张苹果的元数据，发现个怪事——它带 EXIF，而且写着 **`iPhone 16 Pro Max` back triple camera 6.765mm f/1.78**。一张 AI 生成的蜡笔画，凭空多出个 iPhone 相机信息。这是 Codex 生图默认给你盖的假拍摄元数据，每张都盖。这东西发出去等于自带一个假身份证，所以生图之后那步去 EXIF（`exiftool -all=` 或我流水线里的隐私处理）不是可选项，是必须的。

第二个坑更实际：**尺寸不受控**。我要的是 1086×1448 或 1152×1536（都是 3:4），它给我 1254×1254，一个既不是我要的、也不是标准 gpt-image 的尺寸。所以生完得补一刀 `sips` 归一到精确尺寸，而且同一套图必须先把目标尺寸定死再批量，不然出来一堆参差的还得返工。

## 能力得沉下来，但别乱放地方

跑通只是"这次能用"，我要的是"以后每次都顺手"。自然想到写进配置。但**写哪儿**是要较真的：直接塞进全局 CLAUDE.md？那玩意儿每个会话、每个项目都往上下文里加载，不管你这次做不做图。把一整套生图命令、去 EXIF、resize 的配方常驻进去，等于给所有无关会话交一份上下文税，不划算。

更合身的是拆三层：能力和步骤做成一个用户级 skill，只在我真要生图时才加载；免确认这件事——它是"配置"——落到 settings 里放行 `Bash(codex exec:*)`；全局 CLAUDE.md 只留一行指针，写"要生图用那个 skill"，不放配方。

还有个我特意留的心眼：这能力是**吊在外部状态上的**——得这台机器装了 CLI、登录没掉、feature 没被下线。要是写死在 CLAUDE.md 里一句"我会生图"，换台机器或者哪天退了登，就成了睁眼说瞎话。做成 skill 就能在开头自检：`which codex`、查 auth、查 feature，不满足就老老实实报"不可用"，而不是硬着头皮承诺。**优雅降级，这是 CLAUDE.md 那种硬断言做不到的。**

## 最后一轮：被"后台监控"坑了一把，然后想明白了

真拿它去跑批量，栽了。我一开始图省事，让生图挂后台跑，想着不占会话。结果这会话里后台不稳，断了两回，更烦的是——**我没法知道它啥时候好，只能一遍遍去问"生完了没"**。轮询，最蠢的姿势。

坐下来想才发现，我把问题问歪了。我一直在琢磨"怎么给后台加个监控"，可**"监控后台"根本是个伪需求**。真需求是"别让我盯着、别让我问"。顺着这个，正解不是给后台加监控，是**干脆别用后台**：前台逐张生，一张一次独立调用，整批没生完我这回合就不结束，进度就是一条条看得见的调用，你啥都不用问，我生完、验完、处理完一次性把成品端给你。

而且改前台不只是体验问题，是被硬约束逼的：一次 `codex exec` 只出一张、几十上百秒，九张串一个 bash 循环，总时长顶穿单条命令十分钟的超时上限，直接被杀。所以批量本来就只能一张一调。

顺手把抗中断也解决了——**幂等续跑**：每张生成前先看目标文件在不在，在就跳过。于是"断了两回"从灾难变成"再跑一次就接着续，已生成的不重复烧 token"。再加一条逐张即时校验：出一张我 Read 一张，画面和文字逐字核对，不对当场重抽，不拖累后面。

## 说到底

这一趟下来，真正救我的其实不是哪条命令，是两次把问题问对：第一次，"我要的不是让 Claude 会生图，是别转手"；第二次，"我要的不是监控后台，是别让我盯着"。命令谁都查得到，`codex exec` 就摆在 `--help` 里，但你要是一开始奔着"装插件"和"加监控"去，就在错的路上越跑越远。

也别把这法子当银弹。它吊在订阅登录上，吃你的额度和限速；换台机器、退个登就没了；尺寸和元数据都得后期收拾。适用的场景是：你本来就用 Codex 订阅生图、又主力待在 Claude Code、还烦那一手来回转——就我这种。要是你压根没这套流水线，直接上图像 API 反而更干脆。工具顺不顺手，从来都得看你到底站在哪儿干活。
