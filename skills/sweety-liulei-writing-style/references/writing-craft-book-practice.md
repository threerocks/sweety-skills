# 《写作是门手艺》实践系统

本文件把《写作是门手艺》转成 `sweety-liulei-writing-style` 的可执行流程。它不是原书摘抄，也不是读书笔记；它是后续写作、改写、诊断、学习风格时必须执行的工艺路线。

优先级：本文件高于个人口吻规则。旧 skill 中的 profile、样本、AI 腔清理、朱雀边界和素材门禁只在不冲突时辅助本文件。

## 0. 总原则

写作不是装饰文字，而是成人思考的外化。

一篇说理文章要依次解决：

1. 文体：这是不是说理、解释、办事、数据、热点、故事、读书或研究型任务？
2. 读者：读者是谁，为什么要读，能拿走什么？
3. 问题：这篇文章真正回答哪个问号？
4. 输入：材料从哪里来，是否可靠，是否有现实触点？
5. 论证：观点、理由、证据、隐含前提和反方是否成立？
6. 结构：材料之间是什么关系，按什么顺序最省读者力气？
7. 流动：词、句、段、节是否让读者顺着走？
8. 故事：是否用真实事件组织意义，而不是用故事遮蔽事实？
9. 过程：如果卡住，如何推进；如果成稿，如何反馈和归档？
10. 个人风格：最后再进入刘磊口吻、气口、句子节奏和样本学习。

## 1. 任务分流

先判断用户要的不是“文章”这个空壳，而是哪类工件：

| 类型 | 核心工件 | 前置门禁 |
|---|---|---|
| 观点论证 | 问题、主判断、理由、证据、反方 | 论证树 |
| 解释说明 | 概念、机制、例子、边界 | 概念下沉 |
| 办事指南 | 对象、入口、材料、顺序、坑点 | 操作路径 |
| 数据解释 | 数字、口径、对比、影响、误读 | 数据证据门禁 |
| 热点评论 | 可确认事实、争议、判断、反方、行动 | 核验与边界 |
| 读书稿 | 作者问题、材料方法、我补什么 | 输入链与对话定位 |
| 技术/行业分析 | 概念边界、生产场景、机制、反例 | 论证树与证据质量 |
| 标题/开头 | 对象、问题、读者收益、兑现能力 | 问题与可信度 |
| 卡住推进 | 卡点诊断、下一步动作 | 障碍诊断 |

如果用户只给“写一篇 XXX”，默认先进入选题和问题阶段，不直接写正文。

## 2. 文体分流：不要用作文标准写说理文

说理写作不同于作文式表达。作文可以靠情绪、辞藻、名人材料和升华获得表面完整；说理文必须把问题、判断、理由、证据和边界交代清楚。

门禁：

- 说理文不得以“文采、金句、升华、情绪”作为第一标准。
- “像刘磊”不能替代事实可靠、论证完整和读者理解成本。
- 任何“更高级、更有文采”的改法，都必须证明没有遮挡信息。
- 当文字混乱时，先回到问题、材料和论证，不先润色句子。

## 3. 读者门禁

写作像送礼：作者想送什么不重要，读者收到后是否需要、喜欢、用得上才重要。

写正文前生成：

```yaml
reader_profile:
  target_reader: 写给谁
  concrete_names: 可想象的具体读者或用户画像
  reader_interest: 为什么关心
  reader_background: 已知道什么、不知道什么
  reader_stakes: 影响什么选择、损失或收益
  reader_resistance: 可能不同意或读不下去的点
  required_context: 必须补的背景
  can_omit: 可以省略的专业铺垫
```

送礼测验：

1. 这篇文章给读者的礼物是什么：判断、方法、清单、解释、安慰、提醒、工具还是故事？
2. 这是读者要的，还是作者自己想炫的？
3. 读者拿到后能做什么、少走什么弯路、理解什么变化？
4. 读者只读前 200 字，能否知道这份礼物是什么？

语气默认平视：

- 有判断，但不训人。
- 有专业，但不炫技。
- 有边界，但不讨好。
- 不把读者当学生训，也不把读者当领导哄。

## 4. 从题目到问题

题目、议题、现实难题、素材都不是文章。文章必须有问号。

写作前生成：

```yaml
topic_raw: 原始议题或素材
question_line: 这篇文章真正回答的问号
puzzle_line: 读者为什么会觉得这里有反常、矛盾或不解
scope_line: 人群 / 场景 / 时间 / 地域 / 材料 / 动作范围
variable_table:
  dependent_variable: 要解释的结果、差异或变化
  comparison: 谁和谁、何时和何时、哪里和哪里在比较
  constants: 比较对象哪些条件相同
  candidate_causes: 可能影响结果的因素
  mechanism: 因素怎样作用到结果
  evidence_status: 已有事实 / 待查事实 / 只能推测
value_score:
  relevance:
  time_scale:
  contribution:
  welfare_distance:
  finishability:
```

门禁：

- 没有 `question_line`，不写正文。
- 没有 `puzzle_line`，不做爆款标题。
- 没有 `variable_table`，不写分析稿。
- 大题必须至少收窄到人群、场景、时间、地点、材料、动作中的三项。
- 因果判断必须标注证据强度：可验证因果、强相关、弱相关、只是猜测。

常用转换：

- 议题：AI 时代就业。
- 难题：普通人担心被 AI 替代。
- 疑问：同样面对 AI 工具，为什么有的人能做出作品，有的人越学越焦虑？
- 变量：结果差异是作品闭环，自变量可能是任务识别、反馈速度、岗位可迁移性。

## 5. 选题品味与死胡同测试

写什么比怎么写更重要。方法和文风不能拯救低价值、不可完成或无材料的题目。

死胡同测试：

- 问题清晰吗？
- 问题有解吗？
- 材料可得吗？
- 时间够吗？
- 伦理上能写吗？

决策：

- 直接写：问题清楚，材料够，价值和完成性都过线。
- 缩小后写：题大但可收口。
- 先补材料：有问题但输入不足。
- 暂存问题囊：有趣但现在条件不够。
- 放弃：没有问号、无解、不可核验或伦理风险太高。

注意：选题评分服务完成，不能变成拖延系统。普通题目只要可控、有材料、能做深，也可以写。

## 6. 输入链：有字之书与无字之书

没有输入，写作会自然滑向空话、强行升华和廉价判断。

普通深文的最小阅读包：

- 1 条核心材料：直接回答本文问题。
- 1 条背景材料：解释问题从哪里来。
- 1 条对比材料：提供反方、另一面或不同场景。
- 1 条现实材料：访谈、公开案例、评论区典型困境、办事流程、项目过程。
- 1 条核验材料：原始政策、数据源、论文、报告、原视频或原书页码。

材料角色必须标注：

- 观点
- 证据
- 概念
- 案例
- 背景
- 方法
- 反方
- 数据
- 边界

溯源与情境化：

- 谁写的？
- 什么时候写的？
- 写给谁看？
- 基于一手材料、二手材料，还是听闻？
- 作者有什么利益、立场、机构背景或表达目标？
- 这句话、数据或观点处在什么情境？

来源不明的材料不能当证据，只能当舆论现象、误解样本或待核验线索。

## 7. 无字之书门禁

现实议题必须补现实触点。只读屏幕材料，容易缺少成本感和复杂性。

合格现实触点：

- 用户真实经历或项目过程。
- 可匿名普通人案例。
- 公开报道中的具体人物或组织行为。
- 论坛/评论区中可归纳的典型困境。
- 办事流程亲测或官方流程拆解。
- 访谈、口述史、会议纪要、现场观察。
- 行业从业者一手记录。

不合格：

- “很多人都焦虑”。
- “普通人应该提升认知”。
- “网上都在讨论”但没有样本。
- 名人鸡汤或泛泛案例。
- AI 编造的第一人称经历。

涉及职业、教育、家庭、政策、社会阶层、商业、技术落地、组织运行时，至少要有一个现实触点；否则只写资料综述、观点草稿或待补素材清单。

## 8. 文献与资料对话

文献不是装饰。每次引用都要说明它在本文中的角色：支持、反驳、补充、转译、背景或案例。

文献综述流程：

1. 写出核心问题。
2. 记录关键词轨迹：生活词、专业词、同义词、中英文词、排除词。
3. 建立初始文献池：专家推荐、综述、数据库、参考文献顺藤摸瓜。
4. 给文献分类：原创、衍生、背景、方法、理论、案例、数据、反方。
5. 给文献分级：核心、经典、沾边、瞎说、聚集。
6. 用五问化读核心文献。
7. 找凝结核：问题、变量、争议或机制。
8. 选择主结构：时间、问题、攻辩、概念、机制、场景。
9. 写出对话定位：他们说了什么，我要补什么。
10. 停止收集，进入写作。

对话定位模板：

```text
现有说法主要是 A 和 B。
A 解释了什么，B 提醒了什么。
这篇文章接在它们后面，补 C：具体场景、现实成本、反方边界或普通人动作。
```

反驳前必须先准确转述对方最强版本，再指出证据、概念、方法、情境或遗漏问题。

## 9. 最小论证树

好问题只是开始，论证才是交货。

正文前完成：

```text
问题：
核心观点：
论断类型：事实 / 价值 / 政策 / 概念 / 解释
理由 1：
  证据：
  隐含前提：
  可能反方：
理由 2：
  证据：
  隐含前提：
  可能反方：
理由 3：
  证据：
  隐含前提：
  可能反方：
边界：时间 / 地域 / 对象 / 概率 / 条件
```

失败条件：

- 核心观点超过一个，且互相抢主干。
- 观点不能直接回答问题。
- 理由只是重复观点。
- 证据只是例子、名人话或情绪。
- 有因果判断但没有机制、替代解释和适用条件。
- 没有反方或边界。

“先给判断”不等于裸观点。判断后必须马上给理由或证据入口。

## 10. 观点下沉

抽象词必须追问下沉。

- 名词：是哪一种？谁的？哪个场景？哪个时间段？
- 动词：怎么做？谁来做？通过什么入口、工具、制度、流程？
- 形容词：用什么标准判断好坏、强弱、有效、严重？
- 因果词：机制是什么？有没有其他解释？前置条件是什么？
- 政策/建议：成本是什么？替代方案是什么？谁承担代价？

高风险词：

```text
体制机制、认知升级、长期主义、底层逻辑、生态、赋能、闭环、普通人、时代变化、结构性问题、根本原因、有效策略
```

能下沉就改成具体对象、动作和边界。不能下沉就标记为待补材料，不得包装成成熟判断。

## 11. 证据质量门禁

有素材不等于有证据。

每个关键证据过四问：

- 准确性：原意是否被正确转述。
- 精确性：颗粒度是否足够。
- 代表性：能否推广到当前对象。
- 可靠性：来源、时间、层级、是否一手、是否跨领域。

证据适配：

- 量化证据：趋势、规模、比较；说明指标、口径、样本和外推边界。
- 定性证据：过程、意义、机制；说明个案边界，不能直接推出整体。
- 实验证据：因果；说明实验条件。
- 文本证据：概念、话语、制度文本或作品分析；不能替代现实发生。
- 权威证据：补强，不可单独定案；跨界发言降权。

## 12. 谬误与偏误门禁

检查：

- 事实/观点混淆。
- 被质疑后更换话题层级、评价标准或证据要求。
- 用愤怒、委屈、热血替代理由。
- 因为某人说了就算数。
- 只找支持自己观点的材料。
- 把最近发生的事当原因。
- 把最显眼的异常当原因。
- 只看发生了什么，不看没发生什么。
- 认为大结果必有大原因。
- 看到一起变化就写成导致。

处理：

- 低风险表达改成“可能、在这个场景下、更像是、至少说明”。
- 高风险表达补机制、对照和反例；无法补就删除。

## 13. 结构选择

结构不是模板，是材料关系。

流程：

1. 列材料卡：事实、案例、数据、概念、反方、步骤、边界。
2. 标注材料关系：分类、正反、时间、比较、流程、因果。
3. 选择一种主结构，其他作为局部结构。
4. 排序：已知到未知、简单到复杂、共识到争议、普通到特殊、过去到现在。
5. 给每节写功能句：这一节回答什么，为什么放这里。
6. 删除无岗位材料：不能支撑观点、理由、证据或反方的材料先移出。

可选结构：

- 分类：对象多，需要分门别类。
- 评价：正反利弊明显。
- 时间：事件发展明显。
- 比较：两个或多个对象需要判断差异。
- 流程：操作或层级推进。
- 因果：解释原因和后果。

不得默认“背景-原因-方法-总结”。

## 14. 隐性 TAIMRDR

适用于公众号深文、技术观点、研究型长文、政策分析。

- Title：对象 + 问题 + 钩子。
- Abstract/导语：先给判断和阅读理由。
- Introduction：问题是什么，为什么现在值得说。
- Method/材料：案例、数据、文献、经验从哪里来，可信度如何。
- Results/发现：核心发现是什么。
- Discussion：反方、边界、缺陷、下一步。
- References/来源：可复查路径或素材包。

对普通读者不必显式写这些标题，但功能不能缺。讨论部分不能只重复，要承担边界和气口。

## 15. 标题

标题先恰当，再清晰，最后才考虑戏剧性。

流程：

1. 朴素直题：对象 + 问题。
2. 问题化：为什么、怎么、谁、何以。
3. 具体化：删专业词、抽象词和泛泛并列词。
4. 钩子化：加入冲突、反差、悬疑、反问或通俗文化元素。
5. 可信度检查：正文是否兑现，有无恐吓、碰瓷、夸张承诺。
6. 主副标题分工：主标题短，副标题补范围、材料或方法。

没有 `question_line` 和 `puzzle_line`，不得写爆款标题。

## 16. 编码卡与故事

作者在编码，读者在解码。写正文前生成：

```text
读者是谁：
读者已有框架：
读者真正焦虑：
这篇文章的一句话主旨：
主旨里的张力/悖论：
主角或核心问题：
目标：
阻力：
证据来源：
预期知识增量：
不写哪些材料：
不可越过的事实边界：
```

故事不是造事实的许可证。它只是组织真实材料的结构。

故事六问：

- 谁/什么问题是主角？
- 他/它想要什么？
- 为什么想要？
- 他/它做了什么？
- 阻力是什么？
- 代价、后果、发现或边界是什么？

答不出来，就不是故事，只是素材。

技术、行业、学术解释补三问：

- 重要性：和读者的真实焦虑、实际选择或认知困惑有什么关系？
- 挑战性：为什么以前没说清，或为什么普通人容易误解？
- 创新性：这次多提供了什么判断、框架、证据、方法或边界？

## 17. 流动门禁

流动不是文采，而是读者脑内处理成本。

词句：

- 抽象词下沉：定义、例子、动作或场景。
- 主语短、具体、可负责。
- 谓语看得见动作。
- 主谓之间不要塞过多限定。
- 上一句的新信息，尽量成为下一句的起点。
- 长句承载关系，短句负责停顿和加重判断。
- 主动语态默认；被动语态只在客观描述、承接主题或强调被影响对象时用。

段节：

- 一段只说一个意思。
- 关键段第一句尽量给方向。
- 段内主语不要乱跳。
- 小标题必须帮助扫读，不能只是漂亮词。
- 多段之间能标注并列、递进或对比。
- 只读小标题和每段第一句，应能复述全文骨架。

连接词规则：

- 结构层可以有路标词。
- 句内和段内不要堆客服腔、论文腔连接词。
- 普通叙述段优先用短承接：但、所以、还有、重点是、说白了。

## 18. 马奇三原则与情绪配平

写完初稿后三问：

- 有趣：有没有问题张力、反常识、罕见细节或读者焦虑？
- 易懂：目标读者不查术语能否读懂 80%？
- 可信：关键判断是否有证据、来源、案例、方法或边界？

任一不合格，先修素材和结构，不先润色。

说理文章至少自然触发两种情绪：

- 焦虑：问题和读者有关。
- 好奇：为什么会这样。
- 兴奋：出现新路径或新理解。
- 满足：困惑被解释清楚。
- 惊异：常识被可信地修正。

禁止为了情绪编造经历、伪造投稿、制造恐吓或夸大结论。

## 19. 剪裁与边角料

材料不是越多越好。删材料是结构能力。

剪裁三标准：

- 相关：是否服务主问题。
- 比例：是否该重点写、略写、放附录或删除。
- 正当：是否保留必要反证，是否避免误导和捏造。

边角料库：

- 删除但有价值的材料，放入边角料库，不塞回正文。
- 标注删除原因：不相关、比例过重、证据不足、会误导、另文更合适。
- 复盘时检查是否因为舍不得材料破坏主线。

## 20. 长文转展示文档

长文转展示文档不是压缩文章，也不是把段落切成几页。展示文档是现场沟通工件，必须重做读者、时长、顺序和页级功能。

触发：

- 用户说“把文章做成 10 页以内展示文档/PPT/群聊图解/汇报稿/演示稿”。
- 长文、读书稿、研究稿、观点稿需要转成 slides、卡片或现场讲解材料。

先生成展示任务卡：

```yaml
presentation_card:
  audience: 听众是谁
  setting: 群聊 / 会议 / 课堂 / 路演 / 朋友圈 / 公众号配图
  time_budget: 可讲多久或读多久
  after_action: 听众看完要做什么
  one_sentence_takeaway: 只记住一句话是什么
  must_keep: 必须保留的判断、证据、案例、边界
  must_cut: 必须删掉或放边角料的材料
```

从原文抽取 7 类材料：

1. 主问题：这份展示解决什么疑问。
2. 主判断：一页就能讲清的核心结论。
3. 关键证据：最能支撑判断的 1-3 条材料。
4. 对比或机制：为什么不是旧理解。
5. 案例或场景：听众能进入的具体画面。
6. 行动或选择：听众下一步怎么用。
7. 边界或讨论口：哪些地方不能写死。

10 页以内推荐页级功能：

1. 封面判断：对象 + 问题 + 主判断。
2. 读者关系：这事和听众有什么关系。
3. 问题现场：一个具体困境、场景或反常识。
4. 关键发现：最重要的一条结论。
5. 证据页：数据、案例、材料来源或方法。
6. 对比页：错误理解 vs 更好理解，或旧做法 vs 新做法。
7. 机制页：为什么会这样。
8. 行动页：听众现在可以做什么。
9. 边界页：适用范围、反方可能对、不能外推处。
10. 讨论页：一个能引出反馈的问题。

页级门禁：

- 每页只承担一个功能。
- 每页必须有一句可复述的页标题，不写抽象目录。
- 每页正文只放支撑这一页功能的材料。
- 不把长文段落直接粘进页面。
- 不把所有好材料都塞进去；删掉的材料进边角料库。
- 只看页标题，听众应能复述展示骨架。
- 只看最后一页，听众应知道下一步讨论或动作。

低保真输出优先：

```text
Page 1: 封面判断 - ...
Page 2: 读者关系 - ...
Page 3: 问题现场 - ...
...
```

只有低保真页级功能通过后，才进入具体文案、版式和视觉设计。

## 20A. 文章外结论包

文章正文不是完整交付。对作者、编辑和后续学习来说，还必须能看见文章怎么被生产出来。

触发：

- 用户要求写文章、重写文章、视频逐字稿成文、读书稿、观点稿、公众号深文、热点稿、技术解释、发布前定稿。
- 用户反馈“太空泛”“看不出怎么写的”“材料来源不清”“不知道这稿子能不能发”。

交付物：

```yaml
craft_report:
  material_trace:
    - source: 材料来源、链接、文件、逐字稿、评论区样本或用户素材
      role: 观点 / 证据 / 案例 / 背景 / 反方 / 评论样本 / 边界
      used_for: 支撑正文哪个判断、段落或例子
      reliability: 高 / 中 / 低
      limitation: 不能外推、可能误识别、样本偏差或待核验处
  process_trace:
    reader_profile: 写给谁，读者为什么要读
    question_line: 本文真正回答的问题
    puzzle_line: 反常、矛盾或认知缺口
    scope_line: 人群、场景、材料和动作边界
    argument_tree: 主判断、理由、证据、反方和边界
    structure_choice: 采用分类、比较、因果、流程或隐性 TAIMRDR 的理由
    style_profile: 使用的 profile 和口吻取舍
  thinking_notes:
    chosen_angle: 为什么选这个角度
    rejected_angles: 放弃哪些角度，为什么
    key_tradeoff: 为了清楚、可信、篇幅或读者收益牺牲了什么
  quality_scorecard:
    problem_sharpness: 0-10
    material_strength: 0-10
    evidence_fit: 0-10
    argument_integrity: 0-10
    reader_gain: 0-10
    structure_flow: 0-10
    style_fit: 0-10
    originality: 0-10
    fact_boundary: 0-10
    publish_readiness: 0-10
    total: 0-100
    verdict: 可发 / 需补材料 / 只适合作草稿 / 暂不建议写
  risk_boundary:
    - 可能争议、术语不确定、样本不足、未核验事实或人工必须确认处
  next_revision:
    - 下一轮最该补的材料、评论样本、事实核验或结构修改
```

成品分维度评分：

| 维度 | 看什么 | 常见扣分 |
|---|---|---|
| `problem_sharpness` | 问题是否具体、有张力、能回答 | 只有议题，没有问号 |
| `material_strength` | 材料是否足够、来源是否清楚 | 只有单条视频或单个观点 |
| `evidence_fit` | 证据是否真正支撑判断 | 例子只重复观点 |
| `argument_integrity` | 理由、前提、反方和边界是否完整 | 反方缺席，因果跳跃 |
| `reader_gain` | 读者读完拿走什么 | 只是复述材料 |
| `structure_flow` | 顺序是否省力，小标题能否扫读 | 结构来自模板 |
| `style_fit` | 是否像用户本人，且不牺牲信息 | 口语词贴皮 |
| `originality` | 是否有自己的判断或重编码 | 只是摘要 |
| `fact_boundary` | 来源、术语、推测边界是否清楚 | 把 UP 主观点写成行业事实 |
| `publish_readiness` | 是否能进入人工编辑或发布流程 | 缺核验、缺标题、缺评论样本 |

评分规则：

- 总分低于 60：不得称终稿，只能给草稿、骨架或待补素材清单。
- 60-74：内部草稿，必须补材料。
- 75-84：可进入人工编辑，仍需人工确认事实、语气和标题。
- 85 以上：较成熟稿，但仍不能承诺传播效果或检测结果。

材料溯源表必须区分：

- 原始材料：原视频、原书、原报告、官方文件、用户提供素材。
- 衍生材料：逐字稿、摘要、评论区归纳、二手文章。
- 解释材料：作者自己的判断、类比、结构化框架。
- 待核验材料：ASR 可能错词、评论区样本、未经确认的数据或口径。

写作过程可视化建议用短表或 YAML，不写成长篇自我解释。目标是让用户快速看到：材料从哪里来，为什么这么写，哪里还空，下一步怎么补。

## 21. 写作障碍诊断

用户说“卡住、写不出来、没感觉、不知道怎么写、拖着不想写”，先诊断，不直接代写终稿。

```yaml
blockage_diagnosis:
  material_block: 是否没材料
  question_block: 是否没有清楚问题
  structure_block: 是否不知道顺序
  wording_block: 是否想得到但落不了字
  attention_block: 是否被环境和手机打断
  feedback_block: 是否没人纠偏
  fear_block: 是否被终稿标准吓住
```

处理：

- 没材料：补素材、案例、文献、数据。
- 没问题：回到提问门禁。
- 没结构：搭格子，非线性填空。
- 落不了字：口述、语音输入、10 分钟放空式写作。
- 注意力散：25 分钟工作块、断网、远离手机。
- 没反馈：生成具体求助问题。
- 怕写烂：先有后好，只求从 0 到 1。

## 22. 初稿生产：四个角色分离

从零起稿时，分开四个角色：

1. `madman`：列材料、口述想法、写烂句子，不评判。
2. `architect`：把材料分到结构格子，确定问题、主判断、分论点和案例位置。
3. `carpenter`：按格子补段落和过渡，让每段承担功能。
4. `judge`：最后再删、改、查事实、清腔调、调语气。

起稿阶段不要同时做裁判。结构未成时不要纠结标题和第一句。法官阶段不能新增未经核验的事实。

## 23. 反馈回路

反馈不是“帮我看看”。必须具体。

反馈请求模板：

```markdown
我想请你主要看 3 件事：
1. 你读完前 200 字，能不能说出这篇文章想解决什么问题？
2. 第 X 节的判断是否站得住？有没有反例？
3. 哪一段让你最想划掉，哪一段让你想继续读？

背景：这篇写给谁，准备发在哪里，长度目标是多少。
不需要你帮我改字句，优先帮我判断结构、读者障碍和事实风险。
```

反馈归档：

- `feedback_source`：谁给的反馈，外行/内行/目标读者/编辑。
- `feedback_point`：具体意见。
- `action_taken`：采纳、部分采纳、不采纳。
- `reason`：为什么。
- `style_rule`：是否沉淀成可复用规则。

## 24. 四库归档

长期写作靠土壤，不靠临时灵感。

```yaml
writing_archive:
  material_bank: 观察、段子、生活细节、场景
  case_bank: 人物、事件、公司、政策、争议、失败样本
  literature_bank: 书、论文、报告、文章、出处、页码
  data_bank: 数据源、统计口径、年份、链接、可视化可能
  feedback_bank: 人工反馈、读者评论、修改记录
```

事实、引用和案例必须记录出处、时间、页码或链接。案例和素材要区分真实、匿名、合成、虚构。风格 profile 只学习表达策略和删改偏好，不学习一次性事实。

## 25. 后记式写作观

深文要有真实土壤：长期问题、真实反馈、材料积累、项目经验或可核验案例。临时搜索可以补事实，不能伪装成长期判断。

检查：

- 这篇文章解决了作者反复遇到的什么真实问题？
- 它来自课程、项目、失败、读者反馈、材料积累，还是临时拼贴？
- 它是否有自己的声音，而不是论文腔、客服腔、PPT 腔或 AI 完美答案？
- 它是否承认边界、疏漏和可被读者补充的地方？
- 它是否邀请读者参与修正，而不是把读者放在被教育的位置？

目标是：外行能进来，内行不嫌浅。

## 26. 与旧刘磊风格的合并规则

保留：

- 内容密度优先于个人口吻。
- 真实材料、事实锚点、具体入口和边界。
- 去 AI 腔、删除空泛连接词、打破过度整齐。
- 气口、强判断、真实取舍。
- 文风深学习：读取 `diff-notes.md`、`ai-draft.md`、`human-final.md`。
- 朱雀边界：不承诺过检，不做错别字、乱标点、同义词替换。

降级：

- “像刘磊”降到最后一层。
- “气口”不能破坏论证主干。
- “口语粗粝感”不能变成学生腔。
- “传播优化”不能把作文式漂亮话带回来。
- “情感增强”改为经验具体化和场景具体化。
- “删连接词”改为保留必要结构路标，删除机械套话。

最终优先级：

```text
事实可靠性
> 问题和输入链
> 论证树和证据质量
> 读者理解成本
> 结构与流动
> 个人口吻和传播优化
```
