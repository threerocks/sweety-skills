# 可信标题生成

这个 skill 用于写中文内容标题。目标不是制造短期诱点，而是让读者快速知道对象、问题、情绪和点击理由，同时不透支信任。

适用场景：公众号文章标题、小红书图文/滑读卡标题、视频标题、封面主字、社媒贴文标题、作品标题、标题冷审、标题批量候选。

先检查 EXTEND.md，优先级如下：

```bash

test -f "${XDG_CONFIG_HOME:-$HOME/.config}/sweety-skills/sweety-trustworthy-title/EXTEND.md" && echo "xdg"
```

## 输入门槛

生成标题前必须先明确这些字段。若缺关键字段，先问最少问题；不要靠脑补补齐。

| 字段 | 必需性 | 说明 |
|------|--------|------|
| 主题/对象 | 必需 | 写谁、写什么事、哪类内容 |
| 核心观点 | 必需 | 标题要承载的判断、问题或冲突 |
| 目标读者 | 必需 | 谁会点、为什么在乎 |
| 内容类型 | 必需 | 文章、图文、滑读卡、视频、封面字、作品名等 |
| 真实支撑 | 必需 | 正文实际能交付的事实、情节、结果、清单或方法 |
| 对比轴 | 条件必需 | 若内容是原著/动画、原作/改编、前后版本、两种方案对比，必须写清 A 侧、B 侧和差异结论 |
| 历史语境 | 条件必需 | 若内容是历史、人物、制度、文物、城市或考古，必须写清时代、事件/人物和今天读者能看见什么 |
| 希望强调 | 可选 | 数字、反差、使用场景、收藏价值、评论钩子 |
| 需要规避 | 可选 | 禁用词、敏感点、已用模板、平台风险 |

## 标题党硬门禁

任何候选标题命中以下问题，必须重写，不得进入最终输出。

| 类型 | 判定 | 改法 |
|------|------|------|
| 震惊体 | 把普通信息写成大事将至 | 降低情绪，写清具体变化或结果 |
| 恐吓体 | 先堆后果，再慢慢吐信息 | 直接说风险对象和可验证后果 |
| 绑架体 | 用必须看、所有人都该、不看就亏命令读者 | 改成读者能自主判断的价值点 |
| 悬空体 | 只写这件事、这个变化、那个人，不写主语和结论 | 补对象、动作和结论 |
| 碰瓷体 | 硬贴热点、名人、平台或概念，正文没有信息增量 | 删除借势名头，回到正文真实内容 |
| 许诺体 | 标题把效果说满，正文只剩空话 | 把绝对收益改成可交付结果 |
| 对立体 | 把正常分歧写成阵营开战或群体冲突 | 改成具体冲突、选择或误解 |
| 伪投稿 | 标题暗示真实粉丝、读者或来信，但正文无来源 | 改成“一个常见问题”或删除第三方包装 |

额外禁用：

- 不用“内幕”“全网都在”“再不看就晚了”“颠覆认知”“封神”“炸裂”等虚高词，除非正文有强证据。
- 不用空泛副词承担点击理由，例如“超级、巨、特别、非常、真的、必须、绝对、最”。保留时必须跟具体对象、动作、数字或结果。
- 不把标题写成口号、命令或谜语。

## 对比/原著/改编标题硬门禁

当内容类型是“原著与动画差异”“原作与改编对比”“漫画/小说与剧版差异”“改编好坏判断”时，标题必须额外通过以下门禁：

| 门禁 | 判定 | 改法 |
|------|------|------|
| 原作锚点 | 标题必须表达母本/原作侧语义；可以用 `原著`、`原作`、`小说`、`漫画`、`书里`、`原本` 等词，不强制只能写“原著”二字 | 把“这段/这里/他”改成“原作侧语义 + 角色/情节” |
| 改编侧 | 标题必须明确出现 `动画`、`剧版`、`第 X 集`、`新版` 等改编侧词 | 补出动画或剧版，不让读者猜在和谁比 |
| 具体情节 | 标题必须写出角色、事件或设定点，不能只写“这段改了”“差别很大” | 补“韩立救旧人”“某角色删戏”“某设定提前”等 |
| 差异结论 | 标题必须给出差异方向或判断，例如 `改软了`、`删狠了`、`提前了`、`更冷`、`变浅了`、`改得值` | 不写空泛“有差别”“不一样” |
| 1 秒答案 | 一个陌生读者扫一眼，应能复述“这篇讲原著和动画哪一处差异” | 若复述不出来，直接重写 |

反例：

- `韩立救旧人这段，动画把他写软了`：缺母本/原作侧锚点，用户不知道是不是讲原著对比。
- `原著党吵翻了，动画这里真改大了`：主语、事件和差异结论都悬空。
- `凡人这一集，改编到底值不值`：缺具体情节，像泛评。

可用写法：

- `对比原著，动画把韩立救旧人改软了`
- `原著韩立救旧人更冷，动画改软了`
- `书里韩立救旧人更冷，动画改软了`
- `原著这里先算风险，动画让韩立先救人`

## 历史内容标题硬门禁

当内容类型是“历史人物”“历史事件”“历史制度”“文物/考古”“城市史”“历史剧/动漫拆解后回到真实历史”时，标题必须额外通过以下门禁：

| 门禁 | 判定 | 改法 |
|------|------|------|
| 历史语境 | 标题必须直接出现 `历史`、朝代、时代、年号、地点或事件语境；不能只裸写小众人物名、制度名、文物名 | 把“考成法”改成“历史上的张居正改革/明代考成法” |
| 具体锚点 | 标题必须出现人物、事件、制度、城市或文物中的至少一个具体名词 | 不写“古人早就懂了”，改写成“张居正改革/王安石变法/晚清铁路” |
| 现代价值 | 标题必须说明今天读者能看懂、学到、避开什么误读，或和普通人的哪个处境有关 | 加入“教我们看懂/提醒今天的人/普通人能看见” |
| 1 秒答案 | 陌生读者扫一眼，应能复述“用哪个历史对象，讲今天的什么问题” | 若只能复述成“讲一个历史名词”，直接重写 |
| 不做古代管理学 | 不能把古代制度直接等同于 KPI、职场、婚恋或心理问题 | 用“看懂/像但不等于/边界”保留类比距离 |

反例：

- `张居正的考成法，卡住的不只是官员`：缺历史语境，缺今天读者收益，非历史读者不知道为什么要点。
- `考成法背后的权力逻辑`：像论文题，普通读者不知道和自己有什么关系。
- `古代 KPI 早就这么狠了`：现代词抢走历史对象，且类比过度。

可用写法：

- `历史上的张居正改革，教我们看懂制度压力怎么传下来`
- `明代考成法提醒今天的人：制度变快时，压力先到基层`
- `从历史上的张居正改革看，普通人为什么会被制度推着走`

## 生成流程

1. 先把正文压成一句“对象 + 动作/问题 + 结果/判断”。
2. 如果是对比/改编类内容，先压成一句“原作侧 + 改编侧 + 具体情节 + 差异结论”，再写标题。
3. 如果是历史类内容，先压成一句“历史语境 + 具体人物/事件/制度 + 今天读者能看懂的问题/边界”，再写标题。
4. 列出正文能兑现的 3-5 个真实点击理由：数字、反差、场景、结果、选择、稀缺、误解纠正、故事冲突或收藏用途。
5. 从 [references/title-patterns.md](references/title-patterns.md) 选择 2-4 种标题思路，不要所有候选只换同义词。
6. 生成候选标题：默认 20 个；用户要少量时也先在内部扩散，再筛出指定数量。
7. 对每个候选跑硬门禁，删除标题党、悬空、空泛、错配正文和同质化标题。
8. 最终输出时优先给差异明显的候选；如果用户要“直接给一个”，先给首选标题，再给 1 句选择理由。

## 写法要求

- 默认 14-28 个中文字符；封面主字可更短，深度文章可稍长但不能绕。
- 标题必须让读者 3 秒内看懂主题、情绪方向和点击理由；对比/原著/改编类标题要压到 1 秒内看懂对比对象和差异点。
- 历史类标题要压到 1 秒内看懂历史对象和现代读者收益。
- 标题必须和正文强相关，不能预支正文没有交付的结果。
- 多用具体对象、数字、结果词、判断词、动作词。
- 标题之间必须角度不同，不能只是替换同义词。
- 语气自然，像人在认真推荐内容，不像喊口号。
- 有余味可以，但余味来自未说尽的判断，不来自隐瞒主语和结论。

## 输出格式

用户没有指定格式时：

```markdown
1. 标题
2. 标题
3. 标题
...
```

用户要求标题冷审时：

```markdown
## 问题
- [标题]：命中的风险和原因

## 改写
1. 新标题
2. 新标题
```

用户要求“给一个最好的”时：

```markdown
首选：标题
理由：它写清了[对象/动作/结果]，没有预支正文。
```

## 与其他写作 skill 的关系

- 与 `sweety-viral-opening` 同用时：先用本文确定标题，再用 opening skill 写标题后的前三句或首段承接；不要让 opening skill 替代标题判断。
- 与 `sweety-humanize-writing` 同用时：先用本文定标题方向，再用 humanize 清掉口号腔、模板腔和空泛副词。
- 与 `sweety-liulei-writing-style` 同用时：先用本文保证标题清楚可信，再套用用户个人标题偏好。
- 在项目 `AGENTS.md` 明确要求使用本 skill 时，所有标题生成、改写和冷审都必须先加载本 skill。
